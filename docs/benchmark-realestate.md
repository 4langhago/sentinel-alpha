### 데이터 제약 (이 리포트의 모든 제안이 지켜야 하는 조건)
`lib/collect.mjs`, `lib/molit.mjs`, `lib/storage.mjs` 확인 결과:

1. **수집 범위**: 최근 `DEFAULT_MONTHS = 3`개월, `DEFAULT_MAX_CALLS = 900`회. 우선 지역은 수도권·광역시(서울/경기/인천/부산/대구/대전/광주/울산/세종), 실질 커버리지 약 91개 시군구.
2. **롤링 윈도우**: 매일 재수집하며 3개월 밖 데이터는 사라진다. 즉 **장기 시계열이 현재 존재하지 않는다.** 장기 추이가 필요한 기능은 "과거 데이터 아카이브" 선행 작업이 전제.
3. **종목**: 아파트 매매(상세자료 Dev), 아파트 전월세, 오피스텔 매매, 상업업무용 매매, 토지 매매.
4. **필드**: 단지명/법정동/지번/도로명/전용면적/층/건축년도/거래일/금액/월세/거래유형(중개·직거래)/해제여부/지분거래 여부. 아파트 매매 상세자료에만 `dealing_type`, `road_name`, `cdealType`이 있다.
5. **없는 것**: 좌표(위경도), 매물·호가, 세대수·동수·용적률·주차, 학군, 입주물량·분양·미분양, 인구이동, 경사도/일조, 재건축 진행 상황, 관리비. → 호갱노노·아실·직방의 상당수 킬러 기능은 **구조적으로 복제 불가**.
6. **단지 식별의 한계**: 단지 식별키가 **단지명 문자열**뿐이다(`complex-index.json`은 name→sgg_code 배열). 동명 단지가 여러 시군구에 존재하면 섞인다. 아래 제안 중 단지 단위 기능들은 이 키 설계 개선(`sgg_code + name` 복합키)이 사실상 선행 조건이다.
7. **미확인**: 아파트 전월세 API의 계약기간·계약구분(신규/갱신)·종전계약보증금 필드가 실제 응답에 오는지는 코드가 파싱하지 않아 **미확인**. 온다면 "갱신계약 비중·전세 재계약 인상률" 같은 파생 지표가 가능해진다(검증 필요).

## 1. 서비스별 킬러 기능 요약 (웹 검색 기반, 실사용 검증은 아님)

### 호갱노노
- **실거래가 시세 지도**: 국토부 실거래가를 지도 위 단지 단위로 직접 얹어 "이 동네가 지금 얼마"를 한 화면에 보여준다. 사용자가 쓰는 이유 = 호가가 아닌 **실제 체결가 기준 지도**.
- **가격 변동/신고가 알림**: 관심 단지의 가격 변화·신고가를 푸시로 알림.
- **단지별 거래량 추이 그래프**: 유동성(팔릴 집인지)을 수치로 판단.
- **다차원 필터**: 평형·세대수·금액·입주년차·용적률·**갭 가격·월세수익률·전세가율**·주차 등으로 단지를 걸러낸다.
- **비-실거래 레이어**: 경사도, 학군(초등 도보거리·중학교 특목고 진학률), 상권·학원가, 입주물량, 인구이동, 개발호재. → 우리 데이터로는 불가.

### 아실 (asil)
- **여러 아파트 가격 비교 차트**: A단지 vs B단지를 한 차트에 겹쳐 그린다. 이게 사실상 아실의 정체성.
- **2006년~현재 매매·전세 동시 비교**: 장기 시계열 + 매매/전세 병렬.
- **갭투자 증가지역 / 전세가율**: 매매가·전세가를 함께 표기해 갭을 직접 보여주고, 지역별 갭투자 거래 증가 순위를 집계.
- **외지인(비거주 투자자) 매입 현황**: 매수자 거주지 기반 — 우리 데이터엔 매수자 정보 없음, 불가.
- 개발계획 지도, 전문가 영상 등 콘텐츠.

### 네이버 부동산
- **매물(호가) × 실거래 결합**: 단지 페이지에서 "지금 나온 매물 호가"와 "최근 같은 평형·비슷한 층 체결가"를 나란히 본다. 매물 데이터가 핵심 자산 → 우리는 복제 불가.
- **평형별 실거래 그래프**: 59㎡/84㎡/114㎡ 등 **평형 단위로 분리된** 월별 평균·최고·최저 가격. ← 이건 우리 데이터로 가능.
- 국토부 신고 데이터 반영 지연 1~3일 안내(데이터 신선도 커뮤니케이션).

### 직방 / 다방
- 직방: **3D 단지투어**(조망·일조), 빅데이터랩(평당가·시세변동률·인구흐름). 다방: 매물 수, 세밀한 옵션 필터, 360 VR·실내 구조도.
- 두 서비스 모두 **매물 중개 플랫폼**이라 우리와 경쟁 축이 다르다. 참고할 것은 UX(필터 UI, 지도-목록 동기화, 조건 저장) 정도.

### KB부동산
- **KB시세 / AI 예측시세**: 자체 산출 시세 지수(대출 담보 기준으로 쓰임). 실거래가 없는 단지도 시세가 나온다.
- **지도 위 다중 지표 토글**: 준공년도·실거래가·매물가·평당가격·세대수·**전세가율**·학군을 지도에서 전환.
- 단지톡(커뮤니티), 대출/세금 연계.

### 부동산지인
- **지역분석**: 시장강도, 시세, 거래량, 수요/입주, 미분양을 한 화면에서 시계열로 비교.
- **수요/입주**: 지역별 적정 수요량 대비 입주 물량 → 공급 과잉/부족 판정. 우리 데이터로 불가(입주·분양 데이터 없음).
- **아파트분석**: 시군구/읍면동 단위 필터로 단지를 걸러 비교.
- 사용자가 쓰는 이유 = "개별 단지"가 아니라 **"지역을 사도 되는가"**를 판단하는 매크로 도구.

## 2. 우리에게 없고, MOLIT 실거래만으로 구현 가능한 기능

각 항목에 근거 데이터와 제약을 명시했다. **불가 항목은 따로 분리**했다.

### A. 평형(면적대)별 시세 분리 — 가장 큰 구멍
현재 `computeStats()`는 단지/지역의 모든 면적을 섞어 중위 평당가를 낸다. 59㎡와 114㎡가 한 통계에 들어가면 사용자가 "우리 집 시세"를 읽을 수 없다. 네이버·호갱노노는 전부 평형 단위로 끊는다.
- 데이터: `area` 존재. 전용면적 구간(~60/60~85/85~102/102~135/135~)으로 버킷팅.
- 산출: 평형별 중위가·중위 평당가·거래건수·월별 추이.

### B. 전세가율 · 갭(매매-전세 차액)
아실·호갱노노·KB 모두 전면에 내세우는 지표.
- 데이터: 같은 단지+같은 면적 버킷에서 `deal_type=TRADE` 중위가와 `rent_type=JEONSE` 중위 보증금을 매칭.
- 제약: 아파트만 가능(오피스텔 전월세는 수집 대상이 아님 — `DEFAULT_SERVICE_IDS`에 `OFFI_RENT` 없음). 표본이 적은 단지는 "산출 불가"로 명시해야 한다.

### C. 월세 수익률 / 전월세 전환율
- 데이터: `MONTHLY` 거래의 보증금·월세 + 매매 중위가. 전환율 = 월세×12 / (매매가−보증금).
- 제약: 같은 단지·면적에 매매와 월세가 모두 있어야 하므로 표본이 얇다. 지역(시군구)+평형 단위 집계가 현실적.

### D. 신고가 배지 / 최고가 랭킹
- 데이터: 수집 윈도우 내 같은 단지·면적 버킷의 직전 최고가와 비교. 3개월 윈도우이므로 **"3개월 내 최고가"로만 표기해야 정직하다.** "역대 신고가"라고 쓰면 거짓이 된다.
- 파생: 시군구별 최고가 단지 TOP N, 평당가 TOP N.

### E. 단지 비교 (2~4개 겹쳐 보기)
아실의 핵심. 우리가 이미 `PriceTrendChart`와 `/complex/:name`을 갖고 있어 조합 비용이 낮다.
- 제약: 3개월 윈도우 → 선이 짧다. 아카이브(항목 K) 이전에는 "최근 3개월 비교"로 한정.

### F. 거래량 지표의 전면화
`trend[].count`는 이미 계산되지만 화면에서 보조로만 쓰인다. 부동산지인/호갱노노는 거래량을 1급 지표로 다룬다.
- 산출: 지역·단지별 월별 거래건수, 전월 대비 증감, 지도 히트맵의 **지표 전환(중위 평당가 ↔ 거래량 ↔ 전세가율)**.
- 주의: 당월은 부분 수집이라 반드시 "집계 중" 표기(TASK_TRACKER에 이미 미해결로 등록된 이슈).

### G. 직거래 비율 / 계약 해제 건수 노출
- 데이터: `dealing_type`(중개거래·직거래), 수집 시 집계된 `stats.cancelled`. 둘 다 이미 파이프라인에 존재하지만 **화면에 전혀 노출되지 않는다.**
- 가치: 직거래 비중이 높은 단지는 특수관계인 거래(가격 왜곡) 가능성이 있고, 해제 건수는 이상거래 신호로 읽힌다. 다른 서비스도 잘 안 보여주는 차별 포인트.
- 제약: 아파트 매매 상세자료에만 있는 필드. 다른 종목은 "해당 없음" 처리.

### H. 층별 가격 프리미엄
- 데이터: `floor`. 저층(1~3층)/중층/고층 구간별 같은 면적 대비 가격차.
- 제약: 총 층수를 모르므로 "고층"의 정의가 상대적 — 단지 내 관측 최대층을 대용치로 쓰고 그 한계를 표기해야 한다.

### I. 필터 확장 + 조건 저장
호갱노노 수준의 필터를 우리 데이터 범위 내에서: 평형 프리셋(전용 59/84/114 원클릭), 전세가율 구간, 월세수익률 구간, 직거래 제외, 지분거래 제외.
- `TradeSearchParams`에 필드 추가 + `api.mjs` 필터 체인 확장으로 대부분 커버된다.

### J. 관심 단지 변동 알림 (인앱)
- 데이터: 일 1회 수집 시점의 단지별 마지막 거래 스냅샷 비교 → 신규 거래/신고가 발생 감지.
- 제약: 푸시/메일 인프라 없음. 우선 **인앱 배지 + 즐겨찾기 화면 "새 거래 N건"**이 현실적. 즐겨찾기가 localStorage 기반이라 서버 알림은 Supabase 이관이 선행.

### K. 실거래 아카이브(장기 시계열) — 인프라 성격
- 현재 매일 3개월치로 덮어쓰므로 데이터가 계속 버려진다. 수집 시 `mergeItems()`가 있으나 `index`는 최신 수집 기준이다.
- 월별 스냅샷 샤드(`archive/{YYYYMM}/...`)를 누적하면 **1년 뒤엔 아실 스타일 장기 차트의 재료가 생긴다.** 오늘 시작하지 않으면 영원히 못 만드는 유일한 항목이라 가치가 시간에 민감하다.
- 미확인: Netlify Blobs 용량·비용 한도 내에서 몇 개월치가 감당 가능한지 검증 필요.

### 구현 불가 (데이터 없음) — 기대치 관리용
| 기능 | 이유 |
|---|---|
| 실제 지도 위 단지 핀(호갱노노식) | 좌표 없음. 지오코딩 API(카카오/네이버) 별도 도입 필요 |
| 매물·호가, 매물 증감 | 매물 데이터 없음 |
| 입주물량·미분양·분양 | 별도 공공데이터(주택공급) 필요 |
| 학군·상권·경사도·일조 | 데이터 없음 |
| 외지인 매입 비중 | 매수자 정보 없음 |
| 세대수·용적률·주차 필터 | 단지 제원 데이터 없음(공동주택 단지 정보 API 별도) |
| KB시세류 예측시세 | 자체 모델링 영역, 실거래 없는 단지는 산출 불가 |

## 3. 우선순위 (임팩트 대비 구현 비용)

비용은 상대 척도(S=반나절, M=1~2일, L=3일+). 임팩트는 "사용자가 이 서비스를 다시 열 이유가 되는가" 기준.

| # | 기능 | 임팩트 | 비용 | 선행 조건 | 판정 |
|---|---|---|---|---|---|
| 1 | A. 평형별 시세 분리 | 매우 높음 | M | 없음 | **즉시** |
| 2 | B. 전세가율·갭 | 매우 높음 | M | 단지 식별키 개선 권장 | **즉시** |
| 3 | E. 단지 비교 차트 | 높음 | M | `/complex` 다중 조회 | **즉시** |
| 4 | D. 신고가/최고가 랭킹 | 높음 | S | 없음 | **즉시** |
| 5 | G. 직거래·해제 건수 노출 | 중간(차별성 높음) | S | 없음 | 즉시 |
| 6 | F. 거래량 1급 지표화 + 지도 지표 토글 | 높음 | M | 당월 미확정 표기 | 다음 |
| 7 | I. 필터 확장 | 중간 | S~M | 1·2 완료 후 의미 | 다음 |
| 8 | K. 아카이브 축적 | 장기 매우 높음 | M | Blobs 용량 검증 | **지금 시작**(가치가 시간에 비례) |
| 9 | C. 월세 수익률 | 중간 | M | 표본 부족 처리 | 다음 |
| 10 | H. 층별 프리미엄 | 중간 | S | 총층수 부재 명시 | 다음 |
| 11 | J. 관심단지 변동 알림 | 높음 | L | 즐겨찾기 서버 이관 | 이후 |
| 12 | 단지 식별키 `sgg_code+name` 복합키 전환 | (기반) | M | — | 1·2·3의 정확도 전제 |

정리하면 **1~4를 먼저 치고, 8(아카이브)은 병렬로 오늘 시작**하는 게 합리적이다. 12는 1~3의 품질을 좌우하므로 같이 묶어 처리하는 편이 낫다.

## 4. 상위 3개 구현 스케치

### 4-1. 평형별 시세 분리

**새 파일**
- `src/utils/areaBucket.ts`
  ```ts
  export interface AreaBucket { key: string; label: string; min: number; max: number }
  export const AREA_BUCKETS: AreaBucket[]   // ~60 / 60~85 / 85~102 / 102~135 / 135~ (㎡)
  export const bucketOf(area: number): AreaBucket
  ```
  라벨은 평 기준 병기("전용 84㎡대 · 25평형"). 기존 `toPyeong()` 재사용.
- `src/components/AreaBucketTabs.tsx` — 평형 탭. 각 탭에 거래건수 뱃지, 표본 3건 미만은 비활성 + "표본 부족".

**수정**
- `netlify/functions/lib/storage.mjs` — `computeStats()`가 `by_area: Record<bucketKey, Stats>`를 추가로 반환. `buildShards()`의 sgg/sido 사전 계산 통계에 그대로 실린다(추가 API 호출 0회).
- `netlify/functions/api.mjs` — `/stats`, `/complex/:name` 응답에 `by_area` 포함. `/trades`에 `area_bucket` 쿼리 파라미터 추가(기존 min/max_area 필터로 변환).
- `src/types/trade.ts` — `RegionStats`/`ComplexDetail`에 `by_area?: Record<string, AreaStats>` 추가.
- `src/pages/ComplexPage.tsx` — 요약 카드 위에 `AreaBucketTabs`. 선택된 버킷으로 `buildTrend()`와 거래 이력 테이블을 필터링.
- `src/pages/SearchPage.tsx` / `TradeFilters.tsx` — 평형 프리셋 칩.

**주의**: 상가·토지는 면적 기준이 달라(건물면적/거래면적) 버킷 경계가 무의미하다. `property_type`이 APARTMENT/OFFICETEL일 때만 노출.

### 4-2. 전세가율 · 갭

**새 파일**
- `src/utils/jeonseRatio.ts`
  ```ts
  interface JeonseRatio {
    available: boolean
    ratio: number | null        // 전세 중위 보증금 / 매매 중위가
    gap: number | null          // 매매 중위가 - 전세 중위 보증금 (원)
    tradeSample: number
    jeonseSample: number
    message?: string            // 표본 부족 사유
  }
  computeJeonseRatio(history: TradeItem[], bucketKey?: string): JeonseRatio
  ```
  최소 표본(매매 2건·전세 2건) 미만이면 `available:false`. 지분거래·계약해제 건은 이미 상류에서 제외됨.
- `src/components/JeonseRatioCard.tsx` — 전세가율 게이지 + 갭 금액 + 표본수 + "무엇을 계산했는지" 각주. `riskScore` 카드의 근거 노출 패턴을 그대로 따른다.

**수정**
- `ComplexPage.tsx` — 리스크 스코어 카드 옆/아래에 배치. 평형 탭(4-1)과 연동해 선택 버킷 기준으로 재계산.
- `netlify/functions/api.mjs` — `/stats`에 지역 단위 `jeonse_ratio` 추가(시군구+평형 단위 중위값). `computeStats()`가 현재 `deal_type=TRADE`만 보므로, 전월세 집계 경로를 별도 함수(`computeRentStats()`)로 신설해야 한다.
- 지도: `RegionMapFallback`의 색상 지표에 "전세가율" 옵션 추가(4-3 이후 F 항목과 함께).

**정직성 요건**: 전세가율은 "같은 단지·같은 평형" 매칭이 원칙인데 표본이 얇다. 매칭 실패 시 조용히 지역 평균으로 대체하면 안 되고, **"이 단지는 산출 불가, 시군구 평균은 N%"로 출처를 분리 표기**해야 한다.
