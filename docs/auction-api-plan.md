조사 근거는 `.omc/research/onbid-integration.md`(초기 조사)와 2026-08-31 리서치 결과다.

| 항목 | 사유 |
|---|---|

| 물건상태(`pbctStatCd`) 조건 검색 | 응답 필드로만 존재 |
| 서버사이드 정렬 | 정렬 파라미터 없음 → 클라이언트 정렬 |
| 물건관리번호 자유검색 | 파라미터 없음 (상세조회 15157247로 단건만) |
| 세부입찰방식(`bidMthodCd`) 조건 검색 | 응답 필드로만 존재 |

**실측으로 해소한 리스크**

- **금액 단위**: **원 단위** 확정 (`apslEvlAmt` 75762000 = 7,576만원). 국토부처럼 ×10,000 하면 **안 된다**. `[확인]`
- **주소 조인**: 응답의 `ltnoPnu`(PNU 19자리) **앞 5자리가 그대로 법정동 시군구코드**. 별도 매핑 테이블 불필요, 실거래와 정확히 조인된다. `[확인]`

## 2. 앞으로 붙일 API (우선순위 순)

> 아래는 전부 **사용자가 data.go.kr에서 직접 활용신청**해야 한다. 신청 후 최대 1시간 반영 지연.

### 우선순위 1 — 국토교통부 전월세 실거래가 3종

## 3. 존재하지 않는 API — 계획에서 제외할 것

### 법원경매 물건 API ❌

**공식 무료 API가 존재하지 않는다** `[확인]`

- data.go.kr의 법원경매 관련 데이터는 한국감정평가사협회가 제공하는 **지역/연도/용도별 통계 10건**뿐. 물건 단위가 아니다.
- 대법원 사법정보공유포털(`openapi.scourt.go.kr`)은 판례·사건 조회 중심. 경매물건 조회 API는 `[미확인 — 확인되지 않음]`
- 물건 단위 데이터는 **CODEF(`developer.codef.io`), 쿠콘 등 유료 민간 SaaS**뿐

**조치**: `.env.example`의 `COURT_API_KEY` 항목은 정부 무료 API를 전제로 적혀 있으나 그런 API는 없다.
→ 항목을 제거하거나, 유료 서비스 키로 재정의할지 결정 필요. **경매+공매 통합 검색은 현재 불가능하다.**

### 미분양주택현황 ❌

국토교통부 통계누리(`stat.molit.go.kr`)에서 **xlsx 수동 다운로드만 가능**. 오픈API 없음 `[확인]`
→ 필요하면 분기별 수동 갱신 정적 파일로 관리

## 4. 구세대 온비드 API — 사용 중단

`http://openapi.onbid.co.kr/openapi/services` 계열(`ThingInfoInquireSvc`, `OnbidCodeInfoInquireSvc` 등)은
**DNS·TCP는 되지만 HTTP 응답 없이 연결을 끊는다.** 2026-08-11과 2026-08-31 두 차례 확인했다. `[확인]`

초기 조사 문서(`.omc/research/onbid-integration.md`)의 "구세대 API 우선" 판단은 **확정적으로 뒤집혔다.**

**정리 대상 파일** — 죽은 엔드포인트를 향하고 있어 현재 무용지물:
- `scripts/probe-onbid.mjs`
- `scripts/dump-onbid-sample.mjs`
